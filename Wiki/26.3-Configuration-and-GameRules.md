## 2. Step-by-Step Configuration Workflow

### In-Game Server Administration (Brigadier Commands)
Server operators (Permission Level 2+) can adjust mechanics on the fly with immediate effect without restarting the server:

1. **Check Current Value**:
   ```mcfunction
   /gamerule bettercrossbows:crossbow_velocity_multiplier
   ```
2. **Modify Parameter**:
   ```mcfunction
   /gamerule bettercrossbows:crossbow_velocity_multiplier 200
   ```
3. **Reset to Default**:
   ```mcfunction
   /gamerule bettercrossbows:crossbow_velocity_multiplier 150
   ```

### Global Default Configuration (`config/bettercrossbows.json`)
When generating **new worlds**, the server initializes its GameRules from the values defined in `config/bettercrossbows.json`. Changes to this JSON file do not overwrite existing worlds; use `/gamerule` for active worlds.

### In-Game Client Settings Screen (YACL + ModMenu)
Players with **ModMenu** and **YetAnotherConfigLib (YACL v3)** installed can open the interactive GUI:
1. Navigate to **Options** -> **Mods** -> **Better Crossbows** -> **Settings (⚙️)**.
2. Adjust interactive sliders for velocity, fireworks, reload ticks, and particle toggles.
3. Click the optional Ko-fi creator support button to support independent development.

## 3. Mathematical Bounds & The Anti-Nanny Invariant

In adherence to the **Player Agency & Anti-Nanny Invariant**, Better Crossbows **never imposes artificial gameplay ceilings or nanny limits**:
- All integer GameRules register with `.range(Integer.MIN_VALUE, Integer.MAX_VALUE)`.
- If an administrator wants arrows to fire at $10,000\%$ speed ($100\times$), or sets reload ticks to $1$, the mod honors the instruction completely.
- Lower-bound safety clamps are enforced strictly where necessary to prevent fatal JVM crashes (e.g. clamping reload ticks at $\ge 1$ tick during math evaluation).

## 7. Developer & API Hooks

### Reading GameRules from Addon Mods
Addons can query the live GameRules directly via `BetterCrossbowsGameRules`:

```java
import net.vanillaoutsider.bettercrossbows.registry.BetterCrossbowsGameRules;
import net.minecraft.world.level.Level;

// Returns the live multiplier as a float (e.g. 1.5f for 150)
float arrowMult = BetterCrossbowsGameRules.getVelocityMultiplier(level);

// Returns live reload ticks (e.g. 25)
int baseTicks = BetterCrossbowsGameRules.getReloadTicks(level);

// Check if juice effects are active
boolean juice = BetterCrossbowsGameRules.isJuiceEnabled(level);
```

### Registration via `DynamicGameRuleManager` (DasikLibrary)
```java
CROSSBOW_VELOCITY_MULTIPLIER = DynamicGameRuleManager
    .integerRule("bettercrossbows:crossbow_velocity_multiplier", CATEGORY, config.crossbowVelocityMultiplier)
    .name("Crossbow Velocity Multiplier")
    .description("Multiplier applied to the base power of arrows (in percent). Default: " + config.crossbowVelocityMultiplier)
    .range(Integer.MIN_VALUE, Integer.MAX_VALUE)
    .register();
```
