## 2. Package Organization & "1 File, 1 Purpose" Blueprint

Better Crossbows follows a strict separation of concerns, separating client-side UI helpers, server-authoritative registries, configuration persistence, and bytecode mixins:

```
net.vanillaoutsider.bettercrossbows/
├── BetterCrossbows.java                 # Mod initializer & SLF4J logger entrypoint
├── client/
│   └── BetterCrossbowsClientHelper.java # Client-only singleplayer world queries (@Environment)
├── config/
│   ├── BetterCrossbowsConfig.java       # Persistent config POJO (config/bettercrossbows.json)
│   ├── ModMenuIntegration.java          # ModMenu config factory provider (@Environment)
│   └── YaclScreenHelper.java            # YetAnotherConfigLib v3 screen builder (@Environment)
├── mixin/
│   ├── AbstractArrowMixin.java          # Inverts gravity according to velocity scaling
│   ├── AnvilMenuMixin.java              # Enforces GameRule max level cap during anvil combines
│   ├── CreativeModeTabsMixin.java       # Filters creative tab enchanted books & flushes cache
│   ├── CrossbowItemMixin.java           # Velocity scaling, reload timing, sonic particle juice
│   ├── EnchantmentMenuMixin.java        # Clamps Ballistics offers in enchanting tables
│   └── ItemCombinerMenuAccessor.java    # Accessor for player field on anvil combining
└── registry/
    ├── BetterCrossbowsEnchantments.java # Registry identifier constants
    └── BetterCrossbowsGameRules.java    # Dynamic namespaced GameRules registration
```

## 5. Technical Highlights & Best Practices

### A. MixinExtras `@WrapOperation` vs Fragile `@ModifyVariable`
In earlier versions, launch power was modified using ordinal `@ModifyVariable`:
```java
// Fragile legacy injection (brittle across bytecode changes):
@ModifyVariable(method = "performShooting", at = @At("HEAD"), argsOnly = true, ordinal = 0)
```
In modern releases, this has been refactored to MixinExtras `@WrapOperation` targeting `shootProjectile`:
```java
@WrapOperation(
    method = "performShooting",
    at = @At(value = "INVOKE", target = "Lnet/minecraft/world/item/CrossbowItem;shootProjectile(...)V")
)
private void bettercrossbows$wrapShootProjectile(..., Operation<Void> original) {
    float multiplier = bettercrossbows$getShotMultiplier(level, weapon);
    original.call(..., power * multiplier, ...);
}
```
This guarantees 100% reliability, immune to local variable reordering by Loom or compiler optimizations.

### B. Screen Isolation Protocol for Dedicated Servers
Minecraft dedicated servers do not include client classes such as `net.minecraft.client.Minecraft` or `Screen`. Calling client APIs in common code causes immediate crashes:
```
java.lang.NoClassDefFoundError: net/minecraft/client/Minecraft
```
To eliminate this hazard:
1. `ModMenuIntegration` and `YaclScreenHelper` are marked with `@Environment(EnvType.CLIENT)`.
2. `BetterCrossbowsClientHelper` encapsulates `Minecraft.getInstance().getSingleplayerServer()` behind client guards.
3. ModMenu entrypoint uses `GuiHelper.getOptionalYaclFactory(...)` from DasikLibrary, which defers classloading until GUI invocation.
